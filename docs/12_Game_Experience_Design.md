# Aleria AI Town 游戏体验设计文档（Game Experience Design）

版本：v1.0

更新时间：2026-08-22

# 1. 文档目的

本文档定义 Aleria AI Town 的游戏化体验设计。

目标：

-   在满足腾讯 AI Town 作业要求的基础上，提高 Demo 的游戏体验。
-   将 AI Agent 世界模拟能力通过直观的 2D 世界展示出来。
-   为未来 Canvas / PixiJS / Cocos 扩展提供设计依据。

核心理念：

> AI负责创造世界生命力，游戏表现负责让玩家感受到世界正在运行。

------------------------------------------------------------------------

# 2. 游戏体验目标

Aleria AI Town 不追求传统大型 RPG 的战斗系统。

核心体验：

    进入小镇

    ↓

    观察NPC生活

    ↓

    与NPC交流

    ↓

    推进世界时间

    ↓

    发现NPC故事

    ↓

    影响世界关系

玩家不是简单操作角色。

而是：

> 一个进入艾莱瑞亚大陆的冒险者，通过互动逐渐了解世界秘密。

# 6. 为什么选择PixiJS方向

候选方案：

## Canvas原生实现

优点：

简单。

缺点：

需要自己处理：

-   Sprite
-   动画
-   渲染管理

------------------------------------------------------------------------

## Cocos Creator

优点：

-   游戏能力强
-   腾讯生态相关

缺点：

-   学习和集成成本更高

------------------------------------------------------------------------

## PixiJS

选择方向。

原因：

-   轻量
-   适合Web
-   与Vue结合自然
-   专注2D渲染

------------------------------------------------------------------------

# 7. 地图系统设计

地图不是静态图片。

而是：

World Object。

例如：

``` json
{
"id":"cafe",

"name":"阳光酒馆",

"type":"location",

"position":{
"x":200,
"y":100
}

}
```

后端负责：

世界位置。

前端负责：

展示。

------------------------------------------------------------------------

# 9. NPC动画设计

## Ryan

性格：

热情剑士。

表现：

-   训练动画

## Shir

性格：

冷静刺客。

表现：

------------------------------------------------------------------------

## Grey

性格：

可靠守护者。

表现：

-   经常停留在城门附近
-   观察环境

# 12. 与World Model的关系

重要原则：

前端不能决定世界。

错误：

    点击NPC

    ↓

    前端修改NPC位置

正确：

    玩家操作

    ↓

    API请求

    ↓

    World Engine

    ↓

    World State更新

    ↓

    前端同步展示

------------------------------------------------------------------------
