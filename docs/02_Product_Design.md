# Aleria AI Town Product Design

Version: v1.2

Last Updated: 2026-08-24

## Phase 1D implementation baseline

当前 MVP 的玩家不是可创建职业的完整 RPG 角色，而是固定 `default-player`。玩家可在曦谷的星辉酒馆、中央公园、晨曦城堡和低语森林之间旅行，观察三名 NPC、推进世界时间、对话，并完成“失踪的孩子”。下文的职业、关系、Memory 和更多地点属于产品演进设想。

## Phase 1E narrative baseline

当前玩家是失去记忆、身带陌生印记的旅人。曦谷的公开历史称人类英雄在终焉战争中击败魔王，但完整历史涉及世界本源、古族牺牲和被封存的盟约；约二十余年前的灰烬战争只让少数人接触到这些真相的碎片。

当前产品不提供职业选择、身份分支或结局选择。玩家通过观察、旅行、确定性任务和只读 NPC Chat 逐步发现角色立场差异；完整事实以 `docs/15_Story_Bible_CN.md` 为准。

# 1. Product Vision

## 1.1 Product Name

Aleria AI Town

## 1.2 Product Positioning

Aleria AI Town is an AI Native Fantasy Simulation Game.

项目定位：

不是传统网页游戏。

不是简单聊天机器人。

而是：

一个由 AI Agent 驱动的小型持续世界。

玩家进入一个幻想小镇，与具有独立人格、状态、目标和记忆的 NPC 共同生活。

核心理念：

> NPC不是等待玩家指令的角色，而是拥有自身生活轨迹的数字居民。

# 3. World Background

## 3.1 World Setting

世界名称：艾莱瑞亚。

当前小镇：曦谷。

约五百年前，终焉战争改变了世界秩序。官方历史称人类英雄击败魔王伊萨尔；Author Truth 则包含衰弱的世界本源、古族牺牲、最后盟约和战后历史改写。

约二十余年前，人类勘探旧遗迹引发灰烬战争。曦谷位于旧战场和封锁区附近，在真实的温暖生活下保留着残缺档案与未解痕迹。

这里成为：

-   冒险者交流中心
-   新故事发生地
-   不同角色相遇的地方

------------------------------------------------------------------------

## 3.2 Player Role

玩家身份：固定的失忆旅人。

玩家已知自己身上存在无法解释的印记，但姓名、职业、过去和印记来源都没有确定答案。

玩家不是传统意义上的救世主。

而是：

进入这个世界，并逐渐认识居民、完成当前救援任务和接触历史碎片的外来者。

------------------------------------------------------------------------

# 6. Player Design

## 6.1 Player Profile

当前实现：

-   固定 ID：`default-player`
-   叙事身份：失忆旅人
-   已知特征：无法解释的印记
-   运行时状态：世界与当前位置

当前不创建名字和职业。以下 Player 创建与职业内容是未来概念，不代表 Phase 1E 已实现能力。

未来可能的玩家创建：

-   名字
-   职业

Example:

``` json
{
  "name":"David",
  "class":"Mage"
}
```

# 7. NPC Character Design

## 7.1 Ryan

Identity:

年轻剑士。

Personality:

-   乐观
-   正义
-   热情

Public Goal:

成为真正的英雄。

Inner Conflict:

相信官方英雄史，却无法解释父亲因保护古族幸存者而被视为叛徒的过去。

Hidden Trait:

害怕史莱姆。

Behavior Pattern:

-   训练
-   帮助新人
-   与朋友交流

Example Dialogue:

玩家：

"你害怕什么？"

Ryan：

"英雄当然什么都不怕......不过史莱姆确实有点难处理。"

------------------------------------------------------------------------

# 7.2 Shir

Identity:

沉默刺客。

Personality:

-   冷静
-   内向
-   少言

Public Goal:

找到被删除的证据，并判断它们应该交给谁。

Inner Conflict:

认为真相不应被埋葬，却知道未经准备的公开也可能伤害无辜者。

Hidden Trait:

喜欢甜食。

Behavior Pattern:

-   夜晚散步
-   买甜点
-   观察他人

Example Dialogue:

玩家：

"你喜欢什么？"

Shir：

"没什么。"

（停顿）

"......草莓蛋糕还不错。"

------------------------------------------------------------------------

# 7.3 Grey

Identity:

成年护卫。

Personality:

-   稳重
-   可靠
-   保护欲强

Background:

参与约二十余年前的灰烬战争和遗迹调查，并在行动中失去同伴。

Goal:

守护现在的伙伴。

Inner Conflict:

知道官方记录并不完整，却担心公开秘密会摧毁当前和平。Grey 没有经历终焉战争。

Behavior Pattern:

-   巡逻
-   帮助居民
-   保护小镇

Example Dialogue:

玩家：

"为什么成为护卫？"

Grey：

"因为曾经有人需要我的保护，而我没有做到。"

------------------------------------------------------------------------

# 9. AI Native Features

## 9.1 Autonomous NPC

NPC根据：

-   Personality
-   State
-   Time
-   Location
-   Memory

生成行为。

------------------------------------------------------------------------

## 9.2 Persistent World

世界状态持续变化。

例如：

Day 1:

Ryan训练。

Day 2:

Ryan认识新的冒险者。

Day 3:

Ryan主动邀请玩家探索。

------------------------------------------------------------------------

## 9.3 Emergent Interaction

未来可以通过 NPC 关系、长期记忆和更多事件产生非固定剧情。当前版本只实现确定性行为、聊天历史和一个有界任务，不把这一愿景写成已完成能力。

------------------------------------------------------------------------

# 10. MVP Scope

Phase 1D 已实现范围：四地点世界、三名角色化 NPC、确定性 Tick、NPC Detail、Mock/真实模型 Chat、固定 Player、五步任务及响应式 DOM 页面。训练场/居民区、玩家职业、长期关系和复杂 Agent 能力不属于当前验收范围。

## Must Have

实现：

-   曦谷展示
-   NPC展示
-   NPC详情
-   Tick推进
-   NPC行动
-   NPC聊天

------------------------------------------------------------------------

## Enhanced Features

当前已经具备简单 Quest 与 Event 持久化。下一阶段的高性价比增强是：

-   Prompt v3 与角色化 Mock
-   像素地图展示层
-   动画与更清晰的任务引导
-   Docker、线上体验和演示材料

------------------------------------------------------------------------

## Future Expansion

未来可以扩展：

-   更多NPC
-   更多地点
-   任务系统
-   战斗系统
-   多人世界

------------------------------------------------------------------------

# 11. Design Principles

## Character First

角色优先。

每个NPC必须具有：

独特人格。

------------------------------------------------------------------------

## Simulation First

模拟优先。

世界应该能够自主运行。

------------------------------------------------------------------------

## Simple But Expandable

简单但可扩展。

MVP保证闭环。

架构保留未来扩展空间。

------------------------------------------------------------------------
